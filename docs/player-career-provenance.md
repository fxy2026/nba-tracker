# Player career response provenance

`GET /api/player` attributes each successful regular-season response, including a
validated empty history, using an optional `provenance` object:

```json
{
  "source": "nba-stats",
  "providerPlayerId": "2544",
  "scope": "regular-season",
  "retrievalKind": "api-response",
  "retrievedAt": "2026-10-03T02:00:00.000Z"
}
```

- `source` is `nba-stats` for `playercareerstats`, or `espn` when the fallback
  succeeds. `providerPlayerId` belongs to that source: an ESPN athlete ID is not
  an NBA player ID. The UI constructs an exact source endpoint link from these
  validated fields. This is attribution, not independent statistical verification.
- `scope` describes the regular-season history returned by this endpoint. The
  rows' `SEASON_ID` values describe seasons; they do not date the retrieval.
- `retrievedAt` is an ISO UTC timestamp recorded after this API reads a successful
  provider response. NBA fetches retain their existing one-hour Next data-cache
  policy, so this may be a cached response. It does **not** establish when the
  upstream provider last updated its data, when a game happened, or when a season
  ended. `retrievalKind` makes that limitation explicit in the contract. Edge or
  browser cache hits retain the response's original timestamp.
- Attribution is generated by this API, never copied from upstream metadata.
  When NBA season rows include `PLAYER_ID`, each must be a matching numeric
  integer; a malformed or contradictory value rejects that provider response
  through the normal fallback path. Tables without the optional identity column
  remain supported; the requested provider ID is attribution, not identity proof.
  Failure responses remain HTTP 503/no-store with null data and no provenance;
  valid empty results remain successful and attributed.
- The normalizer preserves valid attribution and strips unknown metadata fields.
  Malformed declared attribution rejects the response, allowing the browser
  loader to retain its complete last-good snapshot and timestamp. Legacy
  responses without attribution remain readable and display source/time as
  unavailable. No source or time is inferred from season dates or shooting stats.
- `careerShooting.source = nba-career-totals` still means shooting percentages
  came from the same NBA response's direct regular-season career aggregate.
  It is separate from general provenance. A valid NBA shooting aggregate cannot
  accompany an ESPN-attributed snapshot. Missing aggregate rates stay unavailable.
- The existing browser-session memory cache keeps rows, shooting rates, and
  provenance together on failed/malformed/truncated refreshes. A complete
  successful provider switch replaces the whole snapshot without mixing sources.

This adds no database, disk/browser persistence, credentials, endpoint calls,
polling, or paid service. It records source lineage for a later persistence
decision without treating retrieval as proof of freshness or correctness.
