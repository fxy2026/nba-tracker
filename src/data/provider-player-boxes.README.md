# Durable per-game provider snapshots

`provider-player-boxes/<10-digit NBA game ID>.json` is the authoritative checked-in store for normalized, historical-team-unassigned basic player lines. Each file retains its source match ID, acquisition time, validation notes and every saved scalar. Stronger manually verified team snapshots remain in `recovered-player-boxes.json` with their separate provenance.

`provider-player-boxes.json` is a gitignored, deterministic build artifact generated by `npm run data:generate`. Pretest, prebuild, predev, pretest:watch and pretypecheck regenerate it before consumers run. This keeps the existing server-only runtime imports and validation boundary without visitor/provider requests. Use `npm run typecheck` on a clean checkout; the ingestion workflow's `npm test` also generates the aggregate before its direct TypeScript checks.

The generator validates every per-game file with the existing full snapshot validator, rejects unsafe filenames/symlinks, identity mismatches and duplicate provider UUIDs, then atomically replaces the aggregate. A malformed file fails the build without replacing the prior local aggregate; an existing production deployment remains available. It never silently discards good rows to publish a partial replacement.

Ingestion validates the entire accepted batch before writing new files with exclusive-create semantics. Existing saved files and stronger snapshots cannot be overwritten by empty/partial/new provider responses. CI regenerates and checks the aggregate after ingestion, then commits only per-game JSON files and cursor state, once per batch. The aggregate and generator code are outside the automated data-publish allowlist. No quota, cadence, provider permissions or paid resource changed.

This layout is bounded repository persistence, not an unlimited database or a claim of independent historical-team verification. Repository history retains prior snapshots and the pre-migration aggregate.
